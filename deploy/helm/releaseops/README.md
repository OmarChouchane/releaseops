# releaseops Helm chart

The application (Spring Boot, 2 replicas by default) and its MySQL (StatefulSet with a PVC), plus probes,
a NetworkPolicy, a PodDisruptionBudget, a PodMonitor, alert rules and a Grafana dashboard.

Argo CD renders this chart from Git. Terraform never renders it.

## Key values

| Value | Default | Meaning |
|---|---|---|
| `image.repository`, `image.digest` | `ghcr.io/CHANGE_ME/...`, empty | Image reference. The digest is written by the release process, never by hand. |
| `replicaCount` | `2` | App replicas (rolling update, `maxUnavailable: 0`). |
| `secret.existingSecret` | empty | Existing Secret with `mysql-user`, `mysql-password`, `mysql-root-password`. Terraform creates it in the GitOps flow. |
| `config.database.host` | empty | Empty means the in-chart MySQL. Set it for an external database. |
| `progressDeadlineSeconds` | `180` | A rollout without progress after this long is reported failed. |
| `mysql.enabled` | `true` | Set `false` when using a managed database. |
| `networkPolicy.enabled` | `true` | Only app pods may reach MySQL on 3306. |
| `monitoring.enabled` | `true` | Needs the Prometheus Operator CRDs (PodMonitor, PrometheusRule). |

Environment-specific values live in [`../../environments/`](../../environments/), not here.

## Behaviour worth knowing

- Actuator runs on a separate management port (8081) that is not in the Service.
- Liveness does not include the database, so a database outage never causes a restart loop. Readiness does.
- All pods run non-root with a read-only root filesystem and the `RuntimeDefault` seccomp profile.

## Check it locally

```bash
helm lint deploy/helm/releaseops --strict
helm template releaseops deploy/helm/releaseops -f deploy/environments/local/values.yaml
```

`./run.sh validate` runs both. The dashboard JSON is generated by [`tools/gen_dashboard.py`](../../../tools/gen_dashboard.py).
